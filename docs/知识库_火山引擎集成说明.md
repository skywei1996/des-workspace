# DES 知识库与火山引擎集成说明

## 1. 文档目的

本文档用于说明当前 DES 项目中“知识库”能力的端到端实现，包括：

- 在 DES 前端创建知识库
- 直接在 DES 中创建火山引擎远端知识库
- 本地文件上传到火山对象存储 TOS
- 通过 TOS URI 导入火山知识库并触发索引
- 同步文档处理状态
- 回传火山切片结果到 DES 本地数据库
- 在前端展示文档、切片、原文预览

本文档基于当前代码实现整理，不是纯方案设计文档。

---

## 2. 当前整体架构

当前链路分为 4 层：

1. DES 前端
2. DES 后端
3. 火山对象存储 TOS
4. 火山知识库 API

核心流程如下：

```text
DES 前端创建知识库
  -> DES 后端创建本地 KnowledgeBase
  -> 如选择“创建新的远端库”，DES 后端调用火山 collection/create
  -> 返回 remote_resource_id / collection_name

DES 前端上传文件
  -> DES 后端接收文件
  -> DES 后端上传文件到 TOS
  -> 获得 tos://bucket/key
  -> DES 后端调用火山 doc/v2/add
  -> 火山开始解析与建索引

DES 后端轮询 / 手动同步
  -> 调用火山 doc/list / doc/info
  -> 更新本地文档状态 waiting / processing / processed / failed
  -> 文档 processed 后调用火山 point/list
  -> 将切片内容写入本地 KnowledgeDocument.chunks

DES 前端展示
  -> 列表页展示知识库与文档状态
  -> Slice Details 展示本地回传 chunks
  -> Original Docs 展示原文件预览
```

## 3. 主要数据模型

后端主要有两张表：

### 3.1 `knowledge_bases`

定义位置：

- `backend/app/models.py`

关键字段：

- `id`: DES 本地知识库 ID，例如 `kb_xxx`
- `name`: DES 知识库名称
- `remote_provider`: 当前固定为 `volcengine`
- `remote_resource_id`: 火山远端知识库唯一 ID
- `remote_host`: 火山 API Host
- `remote_project`: 火山项目，默认 `default`
- `remote_collection_name`: 火山知识库名称
- `sync_status`: 本地同步状态
- `sync_error`: 最近一次错误
- `sync_info`: 远端同步附加信息

### 3.2 `knowledge_documents`

定义位置：

- `backend/app/models.py`

关键字段：

- `id`: DES 本地文档 ID
- `knowledge_base_id`: 所属本地知识库 ID
- `remote_doc_id`: 火山文档 ID
- `name`: 文档名
- `file_type`: 文件类型，如 `PDF`、`DOCX`
- `status`: `waiting` / `processing` / `processed` / `failed`
- `summary`: 文档摘要或状态说明
- `chunks`: 回传后的切片数组
- `source_url`: 原始文件地址，当前主要是 `tos://...`
- `size_bytes`: 文件大小
- `remote_meta`: 火山返回的原始元数据和同步附加信息

## 4. 前端创建知识库流程

前端实现位置：

- `react-des/src/pages/KnowledgeBase.jsx`
- `react-des/src/utils/knowledgeBaseApi.js`

当前前端能力：

- 支持在 DES 中新建知识库
- 支持直接创建新的火山远端知识库，不再要求手工填写 `resource_id`
- 仍保留“连接已有远端库”的模式

当前创建表单逻辑：

- 默认模式：`Create New Remote KB`
- 可切换模式：`Connect Existing Remote KB`

当用户在 DES 中新建远端库时，前端发送：

```json
{
  "name": "sales",
  "description": "辅助测试",
  "type": "text",
  "teams": [],
  "auto_create_remote": true,
  "remote_resource_id": null,
  "remote_host": "api-knowledgebase.mlp.cn-beijing.volces.com",
  "remote_project": "default",
  "remote_collection_name": "sales"
}
```

如果选择连接已有远端库，则会传入真实 `remote_resource_id`。

## 5. 后端创建火山知识库流程

后端入口：

- `POST /knowledge-bases/`
- 文件：`backend/app/routers/knowledge_bases.py`

核心逻辑：

1. 生成本地知识库 ID
2. 读取前端传入的 `auto_create_remote`
3. 若 `auto_create_remote=true` 且未提供 `remote_resource_id`
4. 调用火山接口：`/api/knowledge/collection/create`
5. 将返回的 `resource_id / collection_name / host / project` 写入本地数据库

火山接口封装位置：

- `backend/app/services/volcengine_knowledge_base.py`

当前创建远端知识库使用：

- `create_remote_collection(...)`

该函数内部调用：

- `POST /api/knowledge/collection/create`

创建时采用的关键配置：

- `data_type = unstructured_data`
- `chunking_strategy = custom_balance`
- `multi_modal = ["image_ocr"]`
- `embedding_model = doubao-embedding-and-m3`
- `index_type = hnsw_hybrid`

说明：当前配置已启用图片 OCR 能力，因此 PDF/图片类内容会进入火山的多模态预处理。

## 6. 文件上传到 TOS 的流程

后端上传入口：

- `POST /knowledge-bases/{knowledge_base_id}/documents/upload`

实现文件：

- `backend/app/routers/knowledge_bases.py`
- `backend/app/services/tos_storage.py`

原因：

火山知识库导入接口当前要求传入可访问 URI，常见为：

- `http://...`
- `https://...`
- `tos://bucket/key`

因此本地文件不能直接交给火山，必须先做“中转”。

当前中转流程：

1. 前端上传文件到 DES 后端
2. 后端通过 `upload_bytes_to_tos(...)` 上传到 TOS
3. 得到 `tos://bucket/key`
4. 后端调用火山文档导入接口

TOS 关键实现：

- `build_object_key(...)`: 生成对象路径
- `upload_bytes_to_tos(...)`: 上传文件
- `get_tos_object_bytes_by_uri(...)`: 读取文件，用于原文预览
- `delete_tos_object_by_uri(...)`: 删除单文件
- `delete_tos_prefix(...)`: 删除整个知识库前缀目录

默认对象 key 结构：

```text
des-knowledge/{knowledge_base_id}/{YYYYMMDD}/{HHMMSS}_{file_name}
```

## 7. 火山知识库文档导入流程

导入火山的主要接口：

- `POST /api/knowledge/doc/v2/add`

对应封装：

- `add_document_by_uri(...)`

调用时会传入：

- `resource_id` 或 `collection_name`
- `project`
- `doc_id`
- `doc_name`
- `doc_type`
- `uri`

导入成功后，后端会：

1. 创建本地 `KnowledgeDocument`
2. 初始化状态为 `waiting`
3. 在 `remote_meta` 中记录火山返回信息
4. 将知识库 `sync_status` 更新为 `indexing`

本地持久化函数：

- `_persist_imported_document(...)`

## 8. 文档状态同步机制

当前后端支持两类状态同步：

### 8.1 文档列表同步

接口：

- `POST /knowledge-bases/{knowledge_base_id}/documents/sync`

火山调用：

- `/api/knowledge/doc/list`

用途：

- 批量获取远端文档状态
- 更新本地文档状态和元数据

### 8.2 单文档详情同步

接口：

- `GET /knowledge-bases/{knowledge_base_id}/documents/{document_id}?refresh=true`

火山调用：

- `/api/knowledge/doc/info`

用途：

- 获取某个文档的最新状态和细节

### 8.3 状态映射规则

当前采用的本地状态：

- `waiting`
- `processing`
- `processed`
- `failed`

映射逻辑：

- `process_status == 0` -> `processed`
- `process_status == 1` 且无失败码 -> `processing`
- `process_status == 1` 且有失败码 -> `failed`
- 远端未出现 -> `waiting`

知识库整体状态：

- 有 `waiting/processing` -> `indexing`
- 全部处理完成 -> `connected`
- 全失败 -> `failed`
- 部分失败部分成功 -> `partial_failed`

## 9. 切片回传机制

### 9.1 为什么之前没有真实 chunk

最初实现只接了：

- `doc/list`
- `doc/info`

这两个接口只能拿到：

- 文档级状态
- 摘要信息
- 统计信息

拿不到真实切片正文。

### 9.2 当前真实切片来源

现在已经接入：

- `POST /api/knowledge/point/list`

对应封装：

- `list_document_points(...)`

同步逻辑：

1. 文档状态变为 `processed`
2. 后端调用 `point/list`
3. 通过 `doc_ids=[remote_doc_id]` 过滤当前文档切片
4. 把返回的 `point_list` 转为本地 `chunks`
5. 存入 `KnowledgeDocument.chunks`

当前实现位置：

- `backend/app/routers/knowledge_bases.py`
- `_fetch_remote_document_chunks(...)`
- `_extract_chunk_text_from_point(...)`

### 9.3 回传后的前端展示

前端 `Slice Details` 页签读取：

- `document.chunks`

如果有真实切片，就展示真实切片；如果没有，则过去会走演示文案兜底。当前已逐步转向真实切片显示。

## 10. 原文预览机制

### 10.1 设计目标

原文预览不能再用 chunk 文本伪装，需要直接展示原始文件。

### 10.2 当前后端接口

#### 原始文件流

- `GET /knowledge-bases/{knowledge_base_id}/documents/{document_id}/preview/raw`

用途：

- 从 TOS 读取原始文件
- 用于 PDF / 图片类型预览

#### 文本预览

- `GET /knowledge-bases/{knowledge_base_id}/documents/{document_id}/preview/text`

用途：

- 对 `docx/txt/md/json/csv` 等文本型文件做预览

### 10.3 当前前端展示策略

文件位置：

- `react-des/src/pages/KnowledgeBase.jsx`

当前策略：

- `png/jpg/jpeg/gif/webp` -> 直接显示图片
- `pdf` -> 内嵌 `iframe` 直接显示 PDF
- `docx/txt/md` -> 以文本/Markdown 风格显示
- `doc` -> 暂不支持稳定预览
- `ppt/pptx/xlsx` -> 当前未做内联预览

说明：

`Original Docs` 主页签和预览弹窗都已经接入真实文件预览逻辑，不应再展示伪造的段落说明。

## 14. 当前已知问题与限制

### 14.1 图片型切片 OCR 噪声

对于图片很多的 PDF、原型稿、设计稿，火山 `point/list` 可能返回：

- `chunk_type = image`
- `content` 中包含 `<KBImage>...</KBImage>`
- OCR 结果中带大量乱码、重复全角空格、异常字符

这类内容不适合直接作为“正文切片”展示。

当前处理建议：

- `Original Docs` 优先看原文预览
- `Slice Details` 对图片型 OCR 内容做降级展示
- 不把明显乱码直接当正文

### 14.2 更优方案尚未完全接入

火山 `point/list` 支持：

- `get_attachment_link=true`

这意味着后续可以考虑直接返回图片切片的临时链接，在前端直接展示“切片图片”，而不是展示 OCR 文本。

这是后续最值得补的方向。

### 14.3 TOS 文件可能丢失

如果 TOS 对象已被删除，但本地数据库还保留 `source_url`，则原文预览会失败，通常表现为：

- `preview/raw` 返回 `502`
- TOS 日志为 `NoSuchKey`

### 14.4 当前多进程/多库问题

在调试过程中，曾出现多个 `uvicorn` 进程同时占用 `8000` 端口、或后端读取到不同 SQLite 数据文件的情况，可能导致：

- 同一个接口命中旧代码
- 当前页面数据与数据库不一致
- 重启后知识库记录丢失或切换

建议调试时始终保证：

- 只保留一个后端进程
- 明确当前使用的数据库文件

## 15. 推荐的标准链路

当前推荐使用方式如下：

### 15.1 新建知识库

1. 在 DES 前端进入 Knowledge Base
2. 点击新建
3. 选择 `Create New Remote KB`
4. 填写知识库名称
5. 由后端自动创建火山远端知识库

### 15.2 上传文档

1. 在知识库详情页点击上传
2. 由 DES 后端上传文件到 TOS
3. 由 DES 后端把 `tos://...` 导入火山知识库
4. 等待火山完成处理

### 15.3 查看状态和切片

1. 文档状态由 `waiting -> processing -> processed`
2. processed 后，后端自动从火山 `point/list` 拉切片
3. 前端 `Slice Details` 展示本地 chunks

### 15.4 查看原文

1. `Original Docs` 使用真实文件预览
2. 图片和 PDF 应直接预览
3. Word 使用文本/Markdown 风格预览

## 16. 后续建议

建议优先补的能力：

1. 接入 `get_attachment_link=true`，对图片型切片直接展示附件图
2. 对 `chunk_type=image` 增加更强的 OCR 噪声识别和过滤
3. 为 `ppt/pptx/xlsx` 增加预览 fallback
4. 统一后端启动入口，避免多个进程/多库问题
5. 在知识库创建时增加更严格的远端校验

## 18. 文档结论

当前 DES 与火山知识库的核心链路已经打通：

- 知识库创建
- 远端火山知识库创建
- 文件上传到 TOS

- 文档删除

- 切片回传

- 图片型切片展示质量
- 多模态切片附件直显
- 调试环境一致性
- 部分文件格式的预览体验
