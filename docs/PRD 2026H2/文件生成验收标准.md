# 文件生成验收标准

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 对话生成文件 |
| 验收范围 | 通过对话或上传文档生成 Word、Excel、PDF、PPT、HTML、Markdown、JPG 文件 |
| 核心要求 | 文件可用、内容完整、数据准确、图表正确 |
| 文档状态 | 待验收 |

> 术语约定：本文所称 Word、Excel、PPT、Markdown、JPG 文件分别指 `.docx`、`.xlsx`、`.pptx`、`.md`、`.jpg/.jpeg` 文件。

---

## 一、验收目标

验证用户通过自然语言对话，或在对话中上传文档后，系统能够理解文件生成需求，并输出指定格式的可用文件。生成结果需满足以下要求：

1. 文件格式、名称和数量符合用户要求。
2. 文件可正常下载，下载后可使用对应软件正常打开。
3. 内容与用户指令及上传文档一致，无关键内容缺失。
4. 数据、计算结果和图表准确，不得编造来源数据。
5. 版式适配对应文件类型，达到可直接阅读和使用的标准。

## 二、验收范围

### 2.1 支持的生成方式

| 生成方式 | 说明 |
| --- | --- |
| 纯对话生成 | 用户通过自然语言描述主题、内容、格式和排版要求 |
| 上传文档生成 | 用户上传一个或多个文档，要求总结、改写、分析或转换为指定格式 |
| 多格式生成 | 用户一次要求生成多个不同格式的文件 |
| 基于数据生成 | 用户提供表格或数据，要求生成统计结果和图表 |

### 2.2 支持的输出格式

Word、Excel、PDF、PPT、HTML、Markdown、JPG（`.jpg/.jpeg`）。

### 2.3 上传文件范围

支持对话入口允许上传的 PDF、Word、Excel、PPT、TXT 和图片等文件。具体文件大小、数量上限及图片文字识别能力以系统现有配置为准。

## 三、通用验收标准

以下标准适用于全部输出格式，任一阻断项不通过，则该次文件生成验收不通过。

| 编号 | 验收项 | 通过标准 | 级别 |
| --- | --- | --- | --- |
| COM-01 | 格式识别 | 用户指定格式后，系统生成对应扩展名和文件类型 | 阻断 |
| COM-02 | 文件可用 | 文件可成功下载并使用对应软件正常打开，无损坏或格式错误 | 阻断 |
| COM-03 | 内容完整 | 用户明确要求的主题、章节、字段和结论均有体现 | 阻断 |
| COM-04 | 指令一致 | 文件语言、结构、篇幅、受众和风格符合用户要求 | 重要 |
| COM-05 | 文件命名 | 文件名可识别，不使用乱码或无意义随机字符串 | 一般 |
| COM-06 | 中文显示 | 中文、数字、标点和特殊字符显示正常，无乱码或字体缺失 | 阻断 |
| COM-07 | 下载反馈 | 生成成功后，对话中展示文件名称、格式及可用的下载入口 | 阻断 |
| COM-08 | 多文件生成 | 用户要求多个格式时，各格式均生成成功且核心内容一致 | 阻断 |
| COM-09 | 内容安全 | 不在文件中泄露其他用户、其他会话或系统内部敏感信息 | 阻断 |
| COM-10 | 失败反馈 | 生成失败时明确说明失败对象和原因，不展示不可用的下载入口 | 重要 |

## 四、上传文档验收标准

| 编号 | 场景 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| UP-01 | 单文档生成 | 上传一个文档并要求生成指定格式 | 系统读取文档内容，生成结果覆盖用户要求的关键信息 |
| UP-02 | 多文档汇总 | 上传多个文档并要求汇总 | 系统区分不同来源，合并内容时不遗漏主要结论，不混淆来源数据 |
| UP-03 | 指定范围 | 要求只处理文档中的指定章节、工作表或页码 | 输出仅使用指定范围，未指定内容不得干扰结论 |
| UP-04 | 内容转换 | 将上传文档转换为另一种格式 | 核心文字、表格、数据和层级结构保持一致 |
| UP-05 | 文档与补充指令 | 上传文档后补充修改要求 | 输出同时遵循原文档内容和用户补充指令 |
| UP-06 | 无法解析 | 上传损坏、加密或不支持的文件 | 系统明确提示无法解析及处理建议，不生成伪完整文件 |
| UP-07 | 空文件 | 上传空文件并要求生成 | 系统提示文件无有效内容，并要求用户补充信息 |
| UP-08 | 来源边界 | 上传材料缺少某项数据但用户要求相关结论 | 系统标识数据缺失，不得自行编造具体数值或事实 |

## 五、数据准确性验收标准

### 5.1 准确性要求

- 来源数据必须与用户输入或上传文档一致，不得擅自修改原始数值。
- 加、减、乘、除、汇总、均值、占比、增长率等计算结果必须使用正确公式和业务口径。
- 数据清洗必须遵循用户指定规则；用户未指定时，不得擅自删除、填充或修改原始数据，清洗行为及影响行数应可说明。
- 同一数据在正文、表格、图表和不同输出格式中必须保持一致。
- 数据缺失、口径不明确或单位不一致时，必须提示用户或在文件中说明，不得默认补造。
- 引用外部数据时，需标明来源和时间；无法确认来源时不得表述为确定事实。

### 5.2 数据验收用例

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| DATA-01 | 原始数据复现 | 抽查的字段名称、数值、日期和单位与来源完全一致 |
| DATA-02 | 合计计算 | 合计值与来源明细重新计算结果一致 |
| DATA-03 | 加减计算 | 差额、增量、余额等结果正确，正负号和计算顺序符合业务含义 |
| DATA-04 | 乘法计算 | 数量乘单价、单项值乘系数等结果正确，单位和精度符合要求 |
| DATA-05 | 除法计算 | 单价、人均值、转化率等结果正确；分母为 0 或空值时不报错、不输出无穷值，并明确标识为不可计算 |
| DATA-06 | 比例计算 | 比例计算口径正确，分子、分母和百分比一致 |
| DATA-07 | 增长率计算 | 按 `(本期值-上期值)/上期值` 计算，基期为 0 时明确标识不可直接计算，特殊口径需说明 |
| DATA-08 | 常用聚合 | 计数、去重计数、平均值、最大值、最小值及分组汇总与明细复算一致；加权平均使用正确权重 |
| DATA-09 | 精度与舍入 | 小数位、百分比、货币精度和四舍五入规则一致，不因中间步骤过早舍入产生超出允许精度的误差 |
| DATA-10 | 排序与筛选 | 排序、Top N 和筛选条件正确，结果与原始数据一致；并列值处理规则明确 |
| DATA-11 | 空值清洗 | 正确区分空值、空字符串、`0` 和“无/未知”；仅按明确规则删除、保留或填充，并说明处理数量 |
| DATA-12 | 重复数据清洗 | 按指定唯一键识别重复记录，保留规则明确；不得将字段相似但业务主键不同的记录误删 |
| DATA-13 | 文本清洗 | 按要求处理首尾空格、重复空格、大小写和全半角；不得改变有业务含义的编码、名称或标点 |
| DATA-14 | 类型与格式清洗 | 数字、日期、百分比、货币和布尔值转换正确；非法值被识别并标记，不得静默转换为错误值 |
| DATA-15 | 单位与口径转换 | 元/万元、秒/分钟、百分数/小数等转换正确，转换前后单位清晰且全表一致 |
| DATA-16 | 日期与时区清洗 | 日期格式、时区和跨日边界处理正确；无法识别或不合法日期需标记，不得自动猜测 |
| DATA-17 | 异常值处理 | 异常值识别规则明确；除非用户要求，不得擅自删除或修正，处理前后数量及影响可核对 |
| DATA-18 | 多表或多文件合并 | 关联键、关联方式和字段映射正确，不因重名、空值、类型或格式差异造成漏配、重复或错配 |
| DATA-19 | 清洗结果可追溯 | 输出或说明清洗规则、处理前后记录数、删除/修改/未匹配数量，关键数据可回溯至来源记录 |
| DATA-20 | 跨格式一致 | 同一任务生成的不同格式文件中，清洗后数据、核心指标和结论一致 |

### 5.3 判定规则

- 原始数值、关键指标、结论性数据错误为阻断问题，允许错误数为 0。
- 仅显示精度不同但未改变业务含义时，可按展示规范处理；同一文件内小数位必须统一。
- 因四舍五入导致的合计差异，必须在允许的末位精度范围内，并保持口径一致。

## 六、图表验收标准

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| CHART-01 | 图表类型 | 图表类型适合数据关系和用户要求，如趋势使用折线图、构成使用饼图或堆叠图 |
| CHART-02 | 数据一致 | 图表数据点与来源表格逐项一致 |
| CHART-03 | 标题与图例 | 标题、图例、坐标轴名称清晰，能够说明图表含义 |
| CHART-04 | 单位与刻度 | 单位、时间范围、百分比和刻度展示正确 |
| CHART-05 | 可读性 | 标签不重叠，文字不截断，颜色可以区分不同系列 |
| CHART-06 | 空值处理 | 空值、零值和异常值的处理方式一致且不造成误导 |
| CHART-07 | 图文一致 | 图表趋势与正文结论一致，不出现相反或夸大的描述 |
| CHART-08 | 文件适配 | 图表在 Word、Excel、PDF、PPT、HTML 和 JPG 中可正常显示，不模糊、不溢出 |

## 七、各格式验收标准

### 7.1 Word

| 编号 | 通过标准 |
| --- | --- |
| WORD-01 | 生成 `.docx` 文件，可使用常见 Word 软件正常打开 |
| WORD-02 | 标题、正文、列表和表格层级清晰，分页无大面积空白 |
| WORD-03 | 图片和图表显示完整，不超出页面边界 |
| WORD-04 | 页眉、页脚、目录等仅在用户要求时生成，内容与正文一致 |

### 7.2 Excel

| 编号 | 通过标准 |
| --- | --- |
| XLSX-01 | 生成 `.xlsx` 文件，可正常打开并识别工作表 |
| XLSX-02 | 表头、数据行、列顺序和工作表名称符合要求 |
| XLSX-03 | 数字、日期、百分比和货币使用正确的数据类型及格式 |
| XLSX-04 | 用户要求计算时，公式或计算结果正确，不出现 `#VALUE!`、`#REF!` 等错误 |

| PDF-03 | 中文字体正常，复制文本时不出现乱码 |
| PDF-04 | 页码顺序正确，跨页表格和段落保持可读 |

| 编号 | 通过标准 |
| --- | --- |
| PPT-01 | 生成 `.pptx` 文件，可使用常见演示软件正常打开 |
| PPT-02 | 每页主题明确，标题与正文内容匹配 |
| PPT-03 | 文字、图片、表格和图表不重叠、不越界、不被截断 |
| PPT-04 | 数据和图表与来源一致，前后页面结论不冲突 |
| PPT-05 | 页面数量和内容深度符合用户要求；未指定时结构至少包含封面、主体和结论 |

### 7.5 HTML

| 编号 | 通过标准 |
| --- | --- |
| HTML-01 | 生成 `.html` 文件，可在主流浏览器中正常打开 |
| HTML-02 | 页面无空白、脚本报错或资源加载失败导致的核心内容缺失 |
| HTML-03 | 标题、正文、表格和图表在常见桌面宽度下显示完整 |
| HTML-04 | 文件中的内部导航、链接和交互控件可正常使用；无交互要求时不强制提供 |
| HTML-05 | 关键内容不依赖仅生成者本机可访问的绝对路径资源 |

### 7.6 Markdown

| MD-03 | 不包含无关的对话话术、生成说明或未闭合代码块 |
| MD-04 | 图片和链接使用有效路径或 URL；无法提供时需明确说明 |

### 7.7 JPG

| 编号 | 通过标准 |
| --- | --- |
| JPG-01 | 生成 `.jpg` 或 `.jpeg` 文件，文件类型与扩展名一致，可使用常见图片查看器正常打开 |
| JPG-02 | 文件可成功下载，对话中展示正确的文件名称、格式和下载入口 |
| JPG-03 | 图片主体、文字、图表和标注完整，无明显裁切、遮挡、错位或内容缺失 |
| JPG-04 | 图片清晰度满足用户要求，文字可辨识，颜色和对比度适合阅读；不得出现异常压缩、花屏或严重失真 |
| JPG-05 | 中文、数字、标点和特殊字符显示正常，无乱码、字体缺失或文字重叠 |
| JPG-06 | 图片可在对话区或 Workspace 中正常预览，预览内容与下载后的原始文件一致 |
| JPG-07 | 用户指定尺寸、比例、方向或分辨率时，输出结果符合要求；未指定时保持合理比例，不拉伸变形 |

## 八、异常与边界验收

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| EX-01 | 用户未指定格式 | 系统询问目标格式，或根据上下文选择格式并明确告知用户 |
| EX-02 | 用户要求不支持的格式 | 明确提示支持的格式，不生成扩展名与内容不一致的文件 |
| EX-03 | 用户要求多个格式 | 分别生成全部指定格式，并清晰展示每个文件的下载入口 |
| EX-04 | 用户中途修改格式 | 以用户最后一次明确要求为准，不重复生成已取消的格式 |
| EX-05 | 内容超长 | 保证文件完整；确需拆分时说明拆分规则和文件关系 |
| EX-06 | 图表数据不足 | 不生成具有误导性的图表，提示缺少的数据或改用表格展示 |
| EX-07 | 文件名重复 | 生成文件不得覆盖已有文件，应使用可识别的版本或时间标识 |
| EX-08 | 网络或服务异常 | 保留对话上下文并提供重试入口，不返回虚假的成功状态 |
| EX-09 | 重复点击生成 | 避免产生无法区分的重复文件；若生成多个版本，应明确版本关系 |
