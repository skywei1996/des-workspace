定时任务 PRD 

| 项目 | 内容 |
| --- | --- |
| 版本目标 | 建立围绕数字员工的定时任务闭环 |
| 核心链路 | 对话创建/编辑/删除 -> 数字员工维度管理 -> 独立 Session 承接结果 |
| 主要用户 | 使用数字员工执行重复性工作的普通用户 |
| 文档状态 | 待评审 |

> 术语约定：本文统一使用“定时任务”。“任务 Session”指一个定时任务独享、用于持续承接该任务执行结果与后续对话的会话。

---

## 一、背景与目标

### 1.1 背景

当前系统支持用户在 Chat 中发起一次性任务，但每天、每周、每月重复发生的事务仍需用户反复手动触发。这类需求通常具有以下特征：

- 重复性高，手动触发成本高；
- 执行时间相对固定，适合由系统调度；
- 需要由特定数字员工持续执行；
- 用户查看结果后，往往还需要在原有语境中追问、补充约束或修改任务。

当前产品缺少的不是一个完整的任务后台，而是一条顺畅的任务闭环：用户能在对话中创建和修改任务，按数字员工查看任务，并在任务结果产生后直接回到对应会话继续处理。

### 1.2 版本目标

1. 用户无需离开对话即可完成定时任务的创建、查看、编辑、查看和删除。
2. 用户可按数字员工查看其名下全部未删除任务，并识别任务状态、下次执行时间。
3. 同一定时任务的历次执行结果进入同一个独立 Session，用户可直达最新结果并继续追问或修改任务。
4. 用户可通过数字员工 Chat 页的定时任务结果入口感知并查看新结果。

### 1.3 成功标准

| 维度 | 判断标准 |
| --- | --- |
| 操作闭环 | 用户可通过对话完成创建、编辑、查看、删除四类核心操作 |
| 管理效率 | 用户可快速判断某数字员工正在执行哪些任务、哪些任务已暂停、哪些任务有新结果 |
| 结果直达 | 用户从任务列表查看结果时，可直接进入对应任务 Session 并定位到最新结果消息 |
| 操作安全 | 创建和编辑在提交前均展示完整配置；删除等高风险操作必须确认；目标不明确时不执行变更 |

## 二、版本范围

### 2.1 本期范围

| 能力 | 说明 |
| --- | --- |
| 对话创建定时任务 | 通过多轮对话补齐信息，用户确认后创建 |
| 对话编辑定时任务 | 支持从创建对话或任务 Session 中修改任务 |
| 查看数字员工名下任务 | 支持对话入口和任务入口，展示全部未删除任务 |
| 对话删除定时任务 | 识别目标任务，确认后删除 |
| 独立任务 Session | 同一任务的历次执行结果写入同一 Session |
| 结果直达 | 从任务列表进入对应 Session，并定位最新结果 |
| 结果感知 | Chat 页提供定时任务结果入口、未读角标和轻提醒 |
| 任务启停 | 支持暂停和恢复任务 |

### 2.2 本期不做

| 不做项 | 说明 |
| --- | --- |
| 页面化创建 | 不提供手动新增定时任务的表单或页面入口 | |
| 执行历史页 | 不展开任务执行历史页面的产品与交互设计 |

### 2.3 关键约束

- 一个定时任务对应一个独立 Session，不按执行次数新建 Session。
- 查看任务结果时，直接进入任务 Session 并定位最新结果，不经过执行历史页。
- 已删除任务不在前台任务列表中展示，但删除不清空既有结果消息和执行记录。

## 三、核心产品决策

### 3.1 一个任务对应一个独立 Session

若同一数字员工的多个定时任务共用一个 Session，任务边界和结果上下文会相互混淆。采用独立 Session 后：

| 价值 | 说明 |
| --- | --- |
| 边界清晰 | 一个 Session 只对应一个定时任务 |
| 上下文稳定 | 用户可围绕该任务的历次结果持续追问 |
| 修改连续 | 用户可在结果上下文中继续修改、暂停或删除任务 |

### 3.2 创建和编辑必须先确认后提交

AI 可以通过多轮对话协助用户补齐和打磨任务，但不能在信息不完整或用户未确认时直接落库。提交前需回显完整任务内容和关键配置，用户明确确认后才调用相应工具。

### 3.3 目标明确时减少冗余确认

- 对编辑操作：能稳定识别目标任务时，直接进入内容修改和最终提交确认，不额外确认“是否是这个任务”。
- 对删除操作：无论目标是否明确，执行删除前都必须二次确认。
- 目标任务无法唯一识别时，必须先展示候选任务供用户选择，不得猜测执行。

## 四、用户场景

| 场景 | 用户示例 | 期望结果 |
| --- | --- | --- |
| 创建任务 | “以后每周一早上 9 点帮我整理 AI 行业简报。” | AI 补齐任务信息并回显完整配置，用户确认后创建，返回下次执行时间 |
| 编辑任务 | “改成每周二早上 10 点。” | 系统定位当前任务，展示更新后配置，用户确认后更新 |
| 基于结果编辑 | “以后总结里加上竞品动态，结论再短一些。” | 系统默认指向当前任务，支持多轮修改，确认后更新任务内容 |
| 查看任务 | “看看你现在在帮我跑哪些定时任务。” | 在当前语境返回该数字员工名下的任务聚合视图 |
| 删除任务 | “把刚才这个提醒删掉。” | 系统定位任务并二次确认；无法定位时先返回候选任务 |
| 查看结果 | 用户点击某任务的“查看结果” | 进入对应任务 Session，定位到该任务最新结果消息 |

## 五、功能需求

### 5.1 对话创建定时任务

#### 5.1.1 字段定义

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 任务名称 | 是 | 1-50 字 |
| 任务内容 | 是 | 1-2000 字 |
| 周期类型 | 是 | 单次、每日、每周、每月 |
| 执行时间 | 是 | 需符合对应周期类型的时间规则 |
| 执行数字员工 | 是 | 默认使用当前对话中的数字员工 |
| 开始日期 | 否 | 默认当天 |
| 结束日期 | 否 | 不填表示长期有效 |

#### 5.1.2 主流程

1. 用户在某数字员工对话中表达定时或周期执行意图。
2. 系统识别为“创建定时任务”。
3. AI 通过多轮对话构建任务内容，并补齐必要字段。
4. 信息完整后，系统回显任务名称、完整内容、周期、执行时间、起止日期和执行数字员工。
5. 系统校验时间配置、用户权限和数字员工能力。
6. 用户明确确认创建。
7. 系统调用 `create_automation_task`。
8. 系统返回创建结果、完整任务配置和下次执行时间。
9. 系统为该任务建立独立 Session；后续执行结果均写入该 Session。

#### 5.1.3 规则

- 用户仅表达模糊意图，如“以后记得提醒我”，系统应继续追问，不得直接创建。
- 用户要求即时执行且没有未来时间或周期意图时，不得误创建定时任务。
- 任务依赖当前数字员工不具备的能力时，不得创建，应提示用户更换数字员工。
- 用户确认前的内容均视为任务草稿，不产生实际调度。

### 5.2 对话编辑定时任务

#### 5.2.1 可编辑字段

任务名称、任务内容、周期类型、执行时间、开始日期、结束日期和任务状态（启用/暂停）。

#### 5.2.2 目标识别优先级

1. 在任务 Session 中发起编辑时，优先指向该 Session 对应的任务。
2. 在创建任务的原对话中使用“刚才那个任务”等指代时，优先指向最近创建或讨论的任务。
3. 无法唯一识别目标任务时，返回候选任务列表，待用户选择后继续。

#### 5.2.3 主流程

1. 用户表达修改意图，系统识别并定位目标任务。
2. AI 通过单轮或多轮对话更新任务草稿。
3. 系统回显更新后的完整任务内容和关键配置。
4. 系统校验时间配置、用户权限和数字员工能力。
5. 用户明确确认更新。
6. 系统调用 `update_automation_task`。
7. 系统返回最新任务配置；周期或执行时间发生变化时，同时返回重新计算的下次执行时间。

#### 5.2.4 规则

- 已删除任务不可编辑。
- 正在执行中的任务不可中途修改，需等待当轮执行结束。
- 仅修改任务内容时，提交前仍需展示更新后的完整内容并确认。
- 修改周期或执行时间后，系统必须重新计算下次执行时间。

### 5.3 任务列表

#### 5.3.1 页面结构

- 页面展示状态筛选、周期筛选、搜索框、任务列表和“添加任务”入口。
- 状态筛选包括：全部、启用中、暂停、已结束。
- 周期筛选包括：全部周期、单次、每日、每周、每月。
- 搜索支持匹配任务名称、数字员工名称和最新执行结果。
- “添加任务”菜单提供“通过对话添加”入口；手动添加不在本期范围。

#### 5.3.2 查询与排序

- 任务列表仅展示当前用户创建且未删除的任务。
- 从自动化任务模块进入时，展示当前用户全部任务；从数字员工 Chat 进入时，仅展示该数字员工关联的任务。
- 暂停和已结束任务继续展示，已删除任务不展示。
- 默认按“启用 -> 暂停 -> 已结束”排序；同一状态内按最新任务推送时间降序排列。
- 状态、周期和搜索条件可组合筛选。

#### 5.3.3 列表字段

| 字段 | 展示规则 |
| --- | --- |
| 任务名称 | 展示任务名称和内容摘要 |
| 状态 | 启用、暂停或已结束 |
| 执行周期 | 展示周期类型、执行时间和起止日期；暂停任务不展示下次执行时间 |
| 数字员工 | 展示当前执行该任务的数字员工 |
| 最新执行结果 | 展示结果状态和摘要；无结果时展示“暂无结果” |
| 操作 | 根据任务状态展示可用操作 |

#### 5.3.4 状态与操作

| 状态 | 查看结果 | 编辑 | 恢复 | 暂停 | 删除 |
| --- | --- | --- | --- | --- | --- |
| 启用 | 支持 | 支持 | - | 支持 | 支持 |
| 暂停 | 支持 | 支持 | 支持 | - | 支持 |
| 已结束 | 支持 | 不支持 | 支持，通过 Chat 重新启用 | - | 支持 |
| 已删除 | 不展示 | 不支持 | 不支持 | 不支持 | 不支持 |

- 点击“查看结果”进入任务 Session，并定位最新结果消息。
- 点击“删除”必须二次确认。
- 无任务或筛选无结果时，展示对应空状态。

#### 5.3.5 通过对话添加任务

1. 用户点击“添加任务”，选择“通过对话添加”。
2. 系统弹出数字员工选择弹窗，展示当前用户有权限使用的数字员工。
3. 用户可搜索并单选数字员工；未选择时，“开始对话”按钮不可用。
4. 用户点击“开始对话”后，进入所选数字员工的 Chat 创建定时任务。

交互规则：

- 搜索支持按数字员工名称和来源说明模糊匹配。
- 搜索无结果时提示“未找到匹配的数字员工”。
- 无可用数字员工时，不允许进入后续创建流程。
- 点击“取消”关闭弹窗，并清空选择和搜索内容。
- 弹窗仅用于选择数字员工，不展示任务配置。

### 5.4 对话删除定时任务

#### 5.4.1 主流程

1. 用户表达删除意图。
2. 系统识别目标任务；无法唯一识别时展示候选任务。
3. 系统展示待删除任务信息，并请求用户确认。
4. 用户确认后，系统调用删除工具。
5. 任务状态变更为“已删除”，不再参与调度和前台展示。
6. 系统返回删除结果。

#### 5.4.2 规则

- 普通单任务删除需二次确认。
- 批量删除属于高风险操作，需以确认卡片形式明确展示影响范围并进行强确认。
- 上下文中没有明确任务对象时，不得执行删除。
- 重复删除已删除任务时，应返回“任务已删除”，不得抛出无解释的系统错误。
- 删除只影响未来调度，不清空既有结果消息和执行记录。
- 删除任务后，不允许用户从历史消息再次进入原任务 Session。
- 面向用户统一使用“删除任务”，不得与“结束任务”混用。

### 5.5 暂停与恢复

- 启用任务可暂停；暂停后不再参与调度，不展示下次执行时间。
- 暂停任务可恢复；恢复后重新计算并展示下次执行时间。
- 暂停不影响既有任务 Session 和历史结果。
- 正在执行中的任务执行暂停操作时，当前执行继续完成，从下一次调度开始生效。
- 已结束任务不支持编辑，但允许用户在 Chat 中发起重新启用。

### 5.6 查看任务结果

#### 5.6.1 主流程

1. 用户点击数字员工chat 页面定时任务按钮，查看该数字员工所有未被删除的定时任务。
2. 查看未读的定时任务。
3. 点击该条任务，系统定位该任务最新一条结果消息。
4. 用户可继续通过对话追问结果、修改配置、暂停或删除该任务。

#### 5.6.2 跳转规则

- 同一任务的所有执行结果写入同一任务 Session。
- 任务尚无执行结果时，仍可进入对应 Session，但不定位消息，并提示“该任务暂未产生执行结果”。
- 结果消息定位失败时，应展示明确提示，不得将用户停留在无解释的会话位置。
- 用户进入任务 Session 后，该任务对应的未读状态立即消除。
- 用户从数字员工 Chat 页的定时任务结果入口进入时，应先看到该数字员工的任务结果聚合视图，再按任务进入对应 Session。

## 六、Session 与结果通知

### 6.1 Session 规则

| 规则项 | 规则 |
| --- | --- |
| 归属关系 | 一个定时任务对应一个独立 Session |
| 创建时机 | 任务创建成功后建立或绑定任务 Session |
| 结果写入 | 同一任务的历次执行结果均追加到该 Session |
| 后续交互 | 用户可在 Session 中追问结果或管理当前任务 |

### 6.2 通知写入

- 每次任务执行完成后，在任务 Session 中追加一条定时任务结果消息。
- 结果消息需明确标识为定时任务通知，不得伪装成对用户上一条普通问题的直接回复。
- 若用户正在该 Session 中进行其他交互，结果消息应在当前轮交互结束后插入，避免打断。

### 6.3 结果感知入口

- 数字员工 Chat 页提供定时任务结果入口，该入口属于本期范围。
- 存在未读结果时，入口展示未读角标，并可触发轻提醒。
- 未读状态在用户进入对应任务 Session 后消除。
- 入口、未读提醒、任务聚合视图和结果跳转使用同一数据口径。

## 七、业务规则

### 7.1 状态机

| 当前状态 | 触发事件 | 目标状态 | 说明 |
| --- | --- | --- | --- |
| - | 创建成功 | 启用 | 创建后进入正常调度 |
| 启用 | 用户暂停 | 暂停 | 停止后续调度 |
| 暂停 | 用户恢复 | 启用 | 重新计算下次执行时间 |
| 启用 | 单次任务执行完成 | 已结束 | 不再生成后续调度 |
| 启用/暂停/已结束 | 用户确认删除 | 已删除 | 不再调度且前台不展示 |

“已删除”为终态；“已结束”用于单次任务自然完成，不等同于用户删除。

### 7.2 时间校验

| 校验项 | 规则 |
| --- | --- |
| 单次任务 | 执行时间必须晚于当前时间 |
| 每日任务 | 必须提供明确执行时刻 |
| 每周任务 | 必须指定至少一个星期几和明确执行时刻 |
| 每月任务 | 必须指定至少一个日期和明确执行时刻；若选择 29/30/31 日且当月不存在该日期，则自动在当月最后一天的原定时刻执行 |
| 起止日期 | 结束日期必须晚于开始日期，且包含结束日期当天的执行时刻 |
| 时区 | 时间解析、调度和展示统一按北京时间处理 |


### 7.4 数字员工异常

| 场景 | 处理规则 |
| --- | --- |
| 数字员工临时离线 | 本轮按失败处理并进入重试策略 |
| 数字员工被删除 | 自动暂停任务，通知用户重新选择执行主体（通知本期不做） |
| 数字员工权限变化 | 本轮失败并记录原因；连续失败后可按既有策略暂停 |（本期不做）

### 7.5 权限

- 普通用户仅可查看和管理自己创建、且与对应数字员工关联的任务及结果。
- 管理员可创建全员定时任务。

## 八、通过chat 创建与更新定时任务 异常与边界

| 场景 | 系统处理 | 用户反馈 |
| --- | --- | --- |
| 创建意图缺少时间 | 继续追问，不创建任务 | 提示补充执行时间 |
| 用户多轮补充任务内容 | 持续更新任务草稿 | 提交前展示完整内容 |
| 编辑目标不明确 | 返回候选任务列表 | 请用户选择目标任务 |
| 删除目标不明确 | 不执行删除 | 提示无法定位任务 |
| 数字员工名下无任务 | 展示空状态 | “该数字员工暂无定时任务” |
| 任务尚未执行 | 进入任务 Session，不定位结果 | 提醒“该任务暂未产生执行结果” |
| 编辑已删除任务 | 拒绝编辑 | “未找到该任务” |
| 编辑正在执行的任务 | 暂不更新 | 提示等待本轮执行结束 |
| 删除数字员工全部任务 | 展示影响范围并强确认 | 明确提示不可继续调度 |
| 结果消息定位失败 | 进入任务 Session 并展示提示 | 说明暂时无法定位最新结果 |


## 十、验收标准

| 编号 | 场景 | 前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- | --- |
| AC-01 | 对话创建 | 用户进入可用数字员工对话 | 输入完整的周期任务需求并确认 | 任务创建成功，返回完整配置和下次执行时间 |
| AC-02 | 信息补齐 | 创建请求缺少必要字段 | 用户逐轮补充信息 | 系统持续维护草稿，确认前不创建任务 |
| AC-03 | 创建确认 | 任务信息已完整 | 用户尚未确认 | 系统提供创建表单，用户可提交表单 |
| AC-04 | 对话编辑 | 上下文可唯一定位任务 | 用户修改时间并确认 | 任务更新成功，下次执行时间重新计算 |
| AC-05 | 结果中编辑 | 用户位于任务 Session | 用户多轮修改任务内容并确认 | 当前任务被更新，Session 不变 |
| AC-06 | 编辑歧义 | 上下文存在多个候选任务 | 用户表达模糊编辑意图 | 系统先展示候选任务，不执行更新 |
| AC-07 | 任务聚合 | 数字员工名下存在多状态任务 | 从对话或任务入口查看 | 展示全部未删除任务，暂停任务无下次执行时间 |
| AC-08 | 暂停恢复 | 任务处于启用或暂停状态 | 用户执行暂停或恢复 | 状态正确流转；恢复后重新计算下次执行时间 |
| AC-09 | 删除确认 | 目标任务可唯一定位 | 用户发起删除但未确认 | 系统不删除任务 |
| AC-10 | 删除完成 | 用户确认删除 | 系统执行删除 | 任务停止调度且不再出现在任务列表中，既有结果保留 |
| AC-11 | 独立 Session | 同一任务已执行多次 | 查看各次结果 | 所有结果均位于同一个任务 Session |
| AC-12 | 结果直达 | 任务已有执行结果 | 点击“查看结果” | 进入正确 Session 并定位最新结果消息 |
| AC-13 | 暂无结果 | 任务尚未执行 | 点击“查看结果” | 进入任务 Session，并提示暂未产生结果 |
| AC-15 | 未读提醒 | 任务产生新的未读结果 | 查看数字员工 Chat 页 | 结果入口展示未读角标和轻提醒 |
| AC-16 | 能力校验 | 任务超出当前数字员工能力 | 用户确认创建 | 系统阻止提交并提示更换数字员工 |
