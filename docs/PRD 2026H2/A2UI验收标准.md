# A2UI 验收标准

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 对话生成 A2UI 表单与图表 |
| 验收范围 | 数字员工根据用户要求在对话中生成可提交表单或指定类型图表 |
| 本期范围 | 表单、饼图、柱状图、折线图、条形图、面积图 |
| 核心要求 | 需求理解准确、组件可用、数据准确、来源可追溯、MCP/API 调用正确 |
| 文档状态 | 待验收 |

> 术语约定：A2UI 指数字员工根据对话上下文生成并展示可交互 UI。本期表单提交可联动 MCP 或 API；图表数据仅来源于当前对话中用户提供的文字、表格、上传材料及已明确获得的 MCP/API 返回结果。

---

## 一、验收目标

验证数字员工能够理解用户在对话中的 A2UI 生成要求，并完成以下能力：

1. 根据用户描述生成字段、结构和交互符合要求的表单。
2. 用户填写表单并提交后，按 Prompt 配置调用指定 MCP 或 API。
3. MCP/API 调用参数与表单字段正确映射，提交结果和失败原因反馈清晰。
4. 根据对话上下文生成饼图、柱状图、折线图、条形图或面积图。
5. 图表中的分类、系列、数值、单位和时间范围与来源内容一致，不编造数据。

## 二、验收范围

### 2.1 场景一：生成并提交表单

用户在对话中说明表单用途、字段、校验或提交要求，数字员工回复可交互表单。用户填写并提交后，系统按数字员工 Prompt 中的配置调用目标 MCP 或 API，并展示处理结果。

### 2.2 场景二：生成图表

用户要求数字员工根据当前对话上下文生成图表。本期支持以下五种图表：

| 图表类型 | 主要适用场景 |
| --- | --- |
| 饼图 | 展示同一总体下各分类的构成占比 |
| 柱状图 | 对比不同分类或不同时间点的数值 |
| 折线图 | 展示连续时间或有序维度的变化趋势 |
| 条形图 | 横向对比分类数据，适合分类名称较长或分类较多的场景 |
| 面积图 | 展示连续趋势及数量规模，或多个系列的累计变化 |

### 2.3 本期不纳入范围

- 除上述五类以外的图表类型。
- 未在 Prompt 中配置目标 MCP 或 API 时，不提供表单提交能力，也不展示提交入口。
- 脱离当前对话上下文自行检索、推测或补造数据。

## 三、通用验收标准

| 编号 | 验收项 | 通过标准 | 级别 |
| --- | --- | --- | --- |
| COM-01 | 意图识别 | 正确识别用户要求生成表单还是图表，不混淆组件类型 | 阻断 |
| COM-02 | 对话内展示 | A2UI 内容在数字员工回复中完整展示，不出现空白或无法加载 | 阻断 |
| COM-03 | 内容一致 | 标题、字段、选项、图表类型和说明符合用户要求及对话上下文 | 阻断 |
| COM-04 | 文字显示 | 文字、数字、单位和标点显示正常，无乱码或截断 | 阻断 |
| COM-05 | 状态反馈 | 加载、提交成功、提交失败和数据不足等状态反馈明确 | 重要 |
| COM-06 | 上下文边界 | 不使用其他用户、其他会话或当前上下文中不存在的数据 | 阻断 |
| COM-07 | 修改要求 | 用户补充或修改要求后，重新生成内容以最后一次明确要求为准 | 重要 |
| COM-08 | 安全性 | 不在组件、请求参数或错误信息中泄露密钥、系统 Prompt 和内部敏感配置 | 阻断 |

## 四、表单生成验收标准

### 4.1 表单内容

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| FORM-01 | 表单用途 | 表单标题和说明能够反映用户描述的业务用途 |
| FORM-02 | 字段完整 | 用户明确要求的字段全部生成，无关键字段缺失或无依据字段 |
| FORM-03 | 字段类型 | 文本、数字、日期、单选、多选、下拉和文本域等类型符合字段含义 |
| FORM-04 | 字段顺序 | 字段顺序符合用户要求；未指定时按业务填写顺序排列 |
| FORM-05 | 标签与提示 | 字段名称、占位提示、选项和单位清晰，无歧义 |
| FORM-06 | 必填规则 | 必填与选填设置符合用户要求，必填字段有明确标识 |
| FORM-07 | 默认值 | 仅在用户要求或上下文有明确值时填入默认值，不擅自补造 |
| FORM-08 | 可操作性 | 输入、选择、修改和清空操作可正常完成；仅在 Prompt 已配置目标 MCP 或 API 时展示并支持提交，组件不重叠、不截断 |

### 4.2 表单校验

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| VALID-01 | 必填校验 | 必填字段为空时阻止提交，并定位或提示缺失字段 |
| VALID-02 | 类型校验 | 数字、日期、邮箱、手机号等字段按配置校验，不合法值不得提交 |
| VALID-03 | 范围校验 | 最小值、最大值、长度、日期范围和选项范围符合用户要求 |
| VALID-04 | 格式清洗 | 提交前按规则处理首尾空格、数字格式等，不擅自修改有业务含义的数据 |
| VALID-05 | 错误保留 | 校验失败后保留用户已填写内容，避免要求用户重复录入 |

## 五、Prompt 与 MCP/API 联动验收标准

### 5.1 Prompt 配置要求

数字员工 Prompt 中应能够描述“什么表单连接哪个 MCP 或 API”。每个需要提交的表单至少明确以下内容：

| 配置项 | 说明 | 示例表达 |
| --- | --- | --- |
| 表单标识或用途 | 用于区分触发 MCP 的表单 | 当用户提交“客户回访登记表”时 |
| 目标连接 | 指定允许调用的 MCP 服务或 API | 调用 `crm-mcp`，或调用客户回访 API |
| 工具或接口 | 指定 MCP 工具或 API 接口 | 使用“创建回访记录”能力，或调用 `POST /visits` |
| 字段映射及格式 | 表单字段与 MCP/API 参数的名称、类型、格式和单位对应关系 | 回访时间映射 `visit_time`，格式为 `YYYY-MM-DD HH:mm:ss` |
| 提交条件 | 何时允许调用及必填条件 | 客户名称、回访时间填写完整后调用 |
| 结果反馈 | 成功或失败时回复用户的内容 | 成功展示记录编号，失败展示可理解原因 |

推荐使用结构清晰、边界明确的 Prompt 表达，例如：

```text
当用户要求填写“客户回访登记表”时，生成包含客户名称、回访时间、回访方式和回访结果的表单。
用户提交且必填字段校验通过后，调用 crm-mcp 的“创建回访记录”能力：
- 客户名称 -> customer_name
- 回访时间 -> visit_time
- 回访方式 -> visit_method
- 回访结果 -> visit_result
调用成功后返回记录编号；调用失败时说明失败原因，不得返回虚假的成功状态。
```

### 5.2 MCP/API 调用验收

| 编号 | 验收项 | 通过标准 | 级别 |
| --- | --- | --- | --- |
| MCP-01 | 目标选择 | 提交表单后仅调用 Prompt 为该表单指定的 MCP/API 及工具或接口 | 阻断 |
| MCP-03 | 参数映射 | 字段名称、值、类型、格式和单位与配置的 MCP/API 参数逐项一致 | 阻断 |
| MCP-04 | 参数边界 | 不向 MCP/API 发送未配置、未展示或与业务无关的用户数据 | 阻断 |
| MCP-05 | 防重复提交 | 提交处理中阻止重复触发；重复点击不得产生重复业务记录 | 阻断 |
| MCP-06 | 成功反馈 | MCP/API 返回成功后，展示明确的成功状态及可用的业务结果 | 重要 |
| MCP-07 | 失败反馈 | MCP/API 超时、拒绝或返回错误时，展示可理解的失败原因，不显示成功状态 | 阻断 |
| MCP-08 | 数据保留 | 调用失败后保留表单内容，用户可修改或重试 |
| MCP-09 | 未配置连接 | 表单未绑定 MCP 或 API 时不得猜测调用目标，提交时触发提醒未配置对应的MCP或API | 阻断 |
| MCP-10 | 配置隔离 | 多个表单绑定不同 MCP/API 时，各表单提交到各自目标，不发生串用 | 阻断 |
| MCP-11 | 字段格式不匹配 | 已配置 MCP/API，但提交字段的名称、类型、格式或单位与目标参数不一致时，提交失败；明确提示不匹配字段及要求，不显示成功状态，并保留已填写内容 | 阻断 |

## 六、图表生成验收标准

### 6.1 通用图表标准

| 编号 | 验收项 | 通过标准 | 级别 |
| --- | --- | --- | --- |
| CHART-01 | 类型识别 | 用户指定的图表类型属于本期范围时，生成对应类型 | 阻断 |
| CHART-02 | 数据来源 | 所有分类、系列和数据点均能在当前对话上下文中找到明确来源 | 阻断 |
| CHART-03 | 数据准确 | 图表数据点与来源逐项一致；计算值可按相同口径复算，错误数为 0 | 阻断 |
| CHART-04 | 内容范围 | 仅使用用户指定的数据范围；未指定时使用与当前问题直接相关的数据 | 阻断 |
| CHART-05 | 标题与图例 | 标题、图例、坐标轴名称能够准确说明图表内容 | 重要 |
| CHART-06 | 单位与口径 | 数值单位、百分比、时间范围和统计口径正确且一致 | 阻断 |
| CHART-07 | 分类与顺序 | 分类、系列及时间顺序与来源一致，排序不会改变数据含义 | 重要 |
| CHART-08 | 空值与零值 | 正确区分空值和 0；处理方式不隐藏数据问题或误导用户 | 阻断 |
| CHART-09 | 可读性 | 标签、图例和数据内容不重叠、不截断，颜色可区分不同系列 | 重要 |
| CHART-10 | 图文一致 | 图表趋势、占比和对比关系与数字员工回复中的文字结论一致 | 阻断 |
| CHART-11 | 数据不足 | 上下文缺少数据或口径不明确时，提示用户补充，不编造图表 | 阻断 |
| CHART-12 | 类型越界 | 用户要求本期不支持的图表时，明确说明支持范围，不以错误类型替代 |

### 6.2 分类型验收标准

| 编号 | 图表类型 | 通过标准 |
| --- | --- | --- |
| PIE-01 | 饼图 | 各扇区分类、数值和占比正确 |
| PIE-02 | 饼图 | 不使用负数作为扇区；数据不适合构成分析时提示用户或建议适合的支持类型 |
| COLUMN-01 | 柱状图 | 分类轴与数值轴正确，柱高与来源数值成比例，正负值方向正确 |
| COLUMN-02 | 柱状图 | 多系列分组关系、图例和顺序正确，不混淆分类与系列 |
| LINE-01 | 折线图 | 时间或有序维度按正确顺序连接，数据点与来源逐项一致 |
| LINE-02 | 折线图 | 缺失数据不默认连接为连续值，补值或断点规则需有明确依据 |
| BAR-01 | 条形图 | 分类标签与数值正确对应，条形长度与来源数值成比例 |
| BAR-02 | 条形图 | 排序符合用户要求；未指定排序时不得通过重排制造误导性结论 |
| AREA-01 | 面积图 | 横轴顺序、边界线和面积对应的数据正确，不使用面积夸大差异 |
| AREA-02 | 面积图 | 多系列堆叠时，各层数值与累计值均可复算，系列顺序和图例一致 |

### 6.3 上下文来源优先级

生成图表时，按以下顺序识别数据来源：

1. 用户当前消息中明确提供的数据。
2. 当前会话中用户此前提供的表格、文字或上传材料。
3. 当前会话中已明确调用并返回的 MCP/API 数据。
4. 数字员工在当前会话中基于上述来源完成且可复算的计算结果。

不同来源存在冲突时，应以用户最新明确说明为准；无法判断时先向用户确认，不得自行选择更有利于结论的数据。

## 七、异常与边界验收

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| EX-01 | 表单要求缺少字段信息 | 根据明确业务语义生成必要字段，存在关键歧义时先询问用户 |
| EX-02 | 用户修改表单字段 | 按最新要求更新字段，已填写且仍适用的数据应保留 |
| EX-03 | 未配置 MCP/API | 表单可展示和填写，但不触发任何调用，仅提醒永固 |
| EX-04 | MCP/API 不可用 | 表单可展示和填写；提交时明确提示服务不可用，不返回成功 |
| EX-05 | 字段格式不匹配 | 目标 MCP/API 要求的字段名称、类型、格式或单位与提交值不一致时，提交失败，提示具体不匹配字段及正确要求，并保留填写内容 |
| EX-06 | MCP/API 调用超时 | 展示超时状态并允许重试，避免超时后产生重复业务记录 |
| EX-07 | 图表无数据 | 不生成空白或伪造图表，提示用户补充数据 |
| EX-08 | 图表数据口径冲突 | 标识冲突项并询问用户，不擅自合并不同统计口径 |
| EX-09 | 用户未指定图表类型 | 根据数据关系选择本期支持的合适类型，并在回复中说明类型 |
| EX-10 | 用户要求不支持的图表 | 告知本期支持的五类图表，等待用户选择或建议合适类型 |
| EX-11 | 上下文发生更新 | 重新生成图表时使用最新数据，并确保旧数据不会混入 |
