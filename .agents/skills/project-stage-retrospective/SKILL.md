# Project Stage Retrospective

## 目标

把零散的项目沟通内容、规划讨论、阶段目标和当前进展，整理成适合阶段复盘汇报的正式内容。

该 skill 的重点不是写业务宣传，而是把项目的技术产品规划、阶段路线和当前进展讲清楚，尤其适合用于：

- 阶段复盘 PPT
- 项目进展汇报
- 技术产品规划总结
- 一页式项目阶段说明

## 适用场景

- 用户希望把一个项目压缩成 1 页 PPT 内容
- 用户要同时写多个项目，但要求“一个项目一页”
- 用户明确要求“只讲技术产品规划和进展，不讲业务”
- 用户提供的是零散对话，需要整理成“阶段一、阶段二、阶段三”的路线图
- 用户希望把能力点重新改写成真正的项目阶段表达，而不是泛泛的模块堆砌

## 核心原则

### 1. 优先写“技术产品规划与进展”，不要先写业务价值

默认聚焦以下内容：

- 技术产品定位
- 能力建设路线
- 平台化方向
- 阶段目标
- 当前完成情况
- 下一步持续演进方向

除非用户明确要求，否则不要展开：

- 商业目标
- 市场价值
- 销售收益
- 宏大业务口号

### 2. 阶段必须是真实的项目推进阶段，不要写成能力清单

错误写法：

- 平台定位
- 双循环架构
- 工具接入
- 风险治理

这种写法更像模块目录，不像阶段。

正确写法应该体现时间顺序或能力递进关系，例如：

- 第一阶段：实现数字员工对话
- 第二阶段：对接 MCP、Skill、Knowledge Base
- 第三阶段：基于用户与 Agent 对话的复盘与能力提升
- 第四阶段：持续演进

判断标准：

- 能不能回答“先做什么，再做什么，最后做什么”
- 能不能体现阶段目标与阶段成果
- 能不能被读者理解为项目推进路线而不是能力列表

### 3. 每一页只保留一个中心表达

如果用户说“一个项目一页”，那一页内容应该围绕一个项目展开，不要混入别的项目。

每页建议只讲：

- 这个项目的技术规划框架
- 这个项目的阶段推进路线
- 当前已完成或正在推进的关键进展

### 4. 写法要偏汇报，不要偏说明书

优先使用：

- 已完成
- 正在推进
- 当前重点
- 下一阶段
- 持续演进

少用：

- 冗长背景解释
- 教科书式定义
- 抽象口号堆叠

## 推荐输出结构

如果用户要写“项目阶段复盘”，优先组织成以下结构。

### 结构 A：一页式项目复盘

适合一个项目一页 PPT。

#### 标题

- 项目名 + 技术规划与阶段进展

例如：

- AIE 平台技术规划与阶段进展
- AI Workmate 技术规划与阶段进展

#### 模块 1：技术产品规划

回答：这个项目想建设成什么。

可写内容：

- 平台定位
- 统一能力建设方向
- 技术架构路线
- 工具链 / 平台化 / 标准化方向

#### 模块 2：阶段路线

回答：项目按什么顺序推进。

推荐写成 3 到 5 个阶段：

- 第一阶段
- 第二阶段
- 第三阶段
- 第四阶段（如果需要）

#### 模块 3：当前进展

回答：目前已经做到哪了。

可写内容：

- 已上线能力
- 已完成接入
- 已验证的结果
- 当前正在推进的重点

#### 模块 4：持续演进

回答：下一步怎么继续做深、做稳、做平台化。

如果项目已经形成清晰路线，建议默认保留“持续演进”这一块。

## 内容压缩规则

### PPT 场景下，优先短句而不是长段

如果内容要放进 PPT，特别是一页式布局，优先：

- 一句只表达一个意思
- 一段最多 2 到 3 句
- 标题尽量控制在一行或两行内

### 阶段标签要短

适合做阶段条或右侧标签的写法：

- 数字员工对话
- MCP/Skill/KB
- 复盘与提升
- 持续演进

不适合直接做小标签的写法：

- 基于用户与 Agent 对话沉淀复盘并反哺能力提升

长句应放到正文，不要放到标签条里。

### 标题和正文分工要明确

标题负责说“这是什么阶段”，正文负责说“这个阶段做什么”。

例如：

- 标题：第二阶段：对接 MCP、Skill、Knowledge Base
- 正文：在对话能力稳定后，继续扩展 Agent 的执行与知识能力。通过接入 MCP 工具、Skill 体系与 Knowledge Base，让数字员工具备查找、调用、执行与知识检索能力。

## 针对本次沟通沉淀出的写法偏好

以下规则来自本次项目阶段复盘写作过程中的明确偏好，可直接复用。

### 1. AIE 项目写法偏好

适合围绕以下方向展开：

- 统一平台能力
- 标准化建设
- 生态集成
- 性能验证
- 持续演进

内容重点：

- NVIDIA AI Enterprise 作为技术底座
- NIM 微服务成熟
- GPU / 推理 / Token 可观测性
- Kubernetes、GPU Operator、CI/CD 集成
- 吞吐量与响应时间等性能结果

### 2. AI Workmate 项目写法偏好

适合按四阶段写：

- 第一阶段：实现数字员工对话
- 第二阶段：对接 MCP、Skill、Knowledge Base
- 第三阶段：基于用户与 Agent 对话的复盘与能力提升
- 第四阶段：持续演进

其中：

- 第一阶段重点是会话入口、角色、上下文、基础交互
- 第二阶段重点是工具调用、技能接入、知识检索
- 第三阶段重点是从真实对话中沉淀复盘，并反哺 Agent 能力
- 第四阶段重点是平台化、标准化、可复用、可治理、可扩展

### 3. “持续演进”建议默认保留

如果用户写的是阶段复盘而不是一次性方案，建议最后一阶段或最后一块保留：

- 持续演进

这样内容会从“当前完成了什么”自然过渡到“后续怎么演进”，更像正式汇报。

## 推荐提问方式

如果用户提供的信息还不够，可以优先问这些问题：

- 这个项目的阶段是按时间推进，还是按能力递进？
- 你要写的是“当前已完成 + 下一步”，还是完整路线图？
- 每个阶段最核心的一句话目标是什么？
- 哪些内容必须保留，哪些业务内容要去掉？
- 这一页最终是给 PPT 用，还是给文档用？

## 常见错误

### 错误 1：把模块写成阶段

例如：

- 架构设计
- 工具接入
- 知识管理

这些可能是能力域，不一定是阶段。

### 错误 2：讲了很多业务，没讲技术推进

如果用户要的是项目阶段复盘，重点应回到：

- 技术能力建设路线
- 阶段完成情况
- 后续演进重点

### 错误 3：标题过长，导致 PPT 排版拥挤

处理方式：

- 阶段条、标签条用短词
- 完整表达放正文

### 错误 4：没有“当前进展”和“下一步”区分

阶段复盘不是只列规划，还要明确：

- 已经做完什么
- 现在推进到哪里
- 后面继续做什么

## 输出示例

### 示例：AI Workmate 四阶段写法

第一阶段：实现数字员工对话

- 先完成数字员工基础对话能力，让用户能够稳定与 Agent 进行自然语言交互。
- 重点打通会话入口、角色设定、上下文保持与基础响应质量。

第二阶段：对接 MCP、Skill、Knowledge Base

- 在对话能力稳定后，继续扩展 Agent 的执行与知识能力。
- 通过接入 MCP 工具、Skill 体系与 Knowledge Base，让数字员工具备查找、调用、执行与知识检索能力。

第三阶段：基于对话复盘与能力提升

- 在用户与 Agent 的交互基础上沉淀复盘机制，识别任务执行中的问题、偏差与高价值经验。
- 再把复盘结果反哺到 Agent 策略、技能调用和知识结构中，形成持续优化的能力闭环。

第四阶段：持续演进

- 在前三阶段能力稳定后，持续推进 Agent 架构、技能体系、知识沉淀和协作模式的迭代演进。
- 逐步把能力沉淀为可复用、可治理、可扩展的标准化平台能力。
