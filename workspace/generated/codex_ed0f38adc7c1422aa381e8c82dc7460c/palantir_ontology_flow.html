Palantir Ontology 建模细化流程

从源数据接入 → 对象建模 → 权限管控 → 可交付规则梳理的完整流水线
数据接入
Step 1
数据源识别与接入
识别内部/外部数据源，建立连接
  • 数据库 / 数仓 / API / 文件
  • 数据源注册与连接配置
  • 全量 / 增量同步策略
Step 2
原始数据探查
理解数据 schema、分布、质量
  • 字段类型 / 空值 / 唯一性
  • 数据分布与异常值检测
  • 血缘关系初步梳理
数据探查报告
数据清洗
Step 3
数据清洗与标准化
去除噪音、统一格式、处理缺失
  • 去重 / 去空 / 异常值处理
  • 字段格式标准化（日期、枚举等）
  • 数据脱敏（敏感字段标记）
Step 4
数据质量校验
建立质量规则并验证通过率
  • 完整性 / 准确性 / 一致性
  • 质量 dashboard 与告警
  • 不合格数据回溯修复
清洗后数据
对象建模
Step 5
对象类型定义
定义 Ontology 对象类型及主键
  • 确定对象类型（如 Customer, Order）
  • 定义主键（Primary Key）
  • 对象描述与业务语义标注
Step 6
属性建模与类型
定义属性字段、类型、约束
  • 属性类型（string, int, double, date...）
  • 值约束（必填、唯一、枚举范围）
  • 派生属性 / 计算字段
Step 7
对象关系映射
建立对象间关联关系
  • 1:1 / 1:N / N:M 关系
  • 外键映射与链接类型
  • 反向引用与聚合关系
Step 8
数据映射配置
将源字段映射到对象属性
  • 源字段 → 属性映射规则
  • 类型转换与表达式映射
  • 映射验证与预览
建模完成
角色权限
Step 9
角色定义与权限策略
定义角色、权限矩阵、访问控制
  • 角色层级（Admin / Editor / Viewer）
  • 对象级 / 属性级 / 行级权限
  • 权限策略配置与测试
Step 10
数据发布与同步
将建模结果发布到 Ontology 服务
  • Ontology 版本管理与发布
  • 同步配置与调度策略
  • 发布后验证与回滚方案
Ontology 就绪
交付输出
✅ 交付物
可消费的 Ontology 数据
下一步可直接进入规则梳理、分析、Workshop 等
  • 对象与属性完整定义文档
  • 数据清洗与质量报告
  • 字段映射与血缘关系图
  • 权限配置清单
  • Ontology 发布版本快照
