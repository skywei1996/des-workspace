01什么是 Palantir Ontology？

核心定义

Palantir Ontology 是 语义层（Semantic Layer），将底层杂乱的原始数据表映射为业务人员可理解的 业务对象（Object Types）及其 属性（Properties）与 关联（Links）。

它位于数据管道（Pipeline）之上，应用层之下，是 Palantir Foundry 与 AIP 平台的 核心抽象层。

  • Object Type — 业务对象类型（如：客户、订单、设备）
  • Property — 对象的属性字段（如：客户姓名、订单金额）
  • Link — 对象间的关系（如：客户→订单）
  • Action — 对象上的业务操作（如：审批、更新状态）

02属性定义全流程详解

属性定义 6 步法

Step 1 — 业务语义建模

与业务方确认属性的业务含义、取值范围、业务规则

Step 2 — 数据源映射

识别属性来自哪些数据源表、哪些字段

Step 3 — 属性类型选择

STRING / INTEGER / DECIMAL / BOOLEAN / TIMESTAMP / GEO / ARRAY / ONTOLOGY_OBJECT

Step 4 — 派生逻辑配置

配置属性计算逻辑（SQL / Python / Transform / 聚合）

Step 5 — 约束与校验

唯一性、非空、值域、格式校验规则

Step 6 — 发布与版本管理

发布到生产环境，启用版本控制与变更追踪

属性定义示例 (YAML)

property_definitions:
  customer_name:
    type: STRING
    source: "customers.name"
    required: true
  total_orders:
    type: DECIMAL
    derived: "SUM(orders.amount)"
    aggregation: SUM

属性融合策略（Fusion Strategy）

  • 优先级覆盖 — 按数据源优先级取最高优先级值
  • 时间戳取最新 — 按事件时间戳取最新数据
  • 合并聚合 — 多个来源的值求和/平均后作为属性值
  • 置信度加权 — 按数据源置信度权重计算加权值

04Object Type 与 Link 关系建模

Object Type 定义

Object Type 是 Ontology 中的 一级业务实体，每个 Object Type 包含一组 Properties 和 Links。

  • 每个 Object Type 有唯一的主键（Primary Key）
  • 支持继承与组合（Extends / Contains）
  • 支持版本化发布（Draft / Published）
  • 可配置搜索索引与全文检索

Link 类型

类型说明基数
ONE_TO_ONE一对一1:1
ONE_TO_MANY一对多1:N
MANY_TO_MANY多对多M:N
HIERARCHICAL层级关系父-子

典型业务模型示例

Link 定义示例

link_definitions:
  customer_orders:
    source: Customer
    target: Order
    type: ONE_TO_MANY
    foreign_key: "orders.customer_id"
  order_products:
    source: Order
    target: Product
    type: MANY_TO_MANY
    through: "order_items"

06最佳实践与性能指标

最佳实践

  • 面向业务建模 — 不要将数据库表直接映射为 Object Type，应从业务概念出发
  • 单一数据源优先 — 同一属性的多个来源应明确优先级和融合策略
  • 属性粒度适中 — 避免过细（拆成数百个属性）或过粗（JSON 大字段）
  • 合理使用派生属性 — 计算密集型属性用 Pipeline 预计算，简单逻辑用表达式
  • 版本控制 — 所有 Ontology 变更通过 Draft→Review→Publish 流程
  • 权限最小化 — 属性级权限控制，敏感字段加密

常见陷阱

  • 将数据库外键直接暴露为属性，应为 Link
  • 忽略时区问题导致时间属性混乱
  • 不同类型的数据源直接拼接未做归一化
  • 未设置属性缓存策略导致性能瓶颈
